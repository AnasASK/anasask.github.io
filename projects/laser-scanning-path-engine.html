Laser Scanning Path Engine

FPGA Motion Control Laser Scanning Microscopy

I designed FPGA-based scan engine that drives galvo mirrors and a piezo stage for laser scanning microscopy. It generates smooth, physically correct drive waveforms using speed and acceleration equations, keeps the beam at constant velocity during photon collection, and outputs through 20-bit DACs. Supports XY, XZ, YZ, and XYZ scanning, bidirectional raster, multi-frame acquisition, and configurable laser line patterns.

Background

Laser scanning microscopes (confocal, two-photon, STED) form images by sweeping a focused beam across the sample. Galvo mirrors handle X and Y, a MIPOS piezo stage handles Z. The problem is these are physical systems with real inertia. If you just send a sawtooth waveform, the galvo overshoots at the turnaround, rings, and takes time to settle. That means non-uniform beam speed, which means distorted pixels.

Many controllers either throw away the edges of each scan line or live with the artifacts. This engine takes a different route: instead of correcting bad motion after the fact, it generates waveforms that the hardware can actually follow cleanly.

How It Works

Each scan line is broken into phases: accelerate up to the target speed, hold constant velocity while collecting photons, decelerate, turn around, repeat. The position at every clock cycle is computed from basic kinematics. A "pixel valid" flag goes high only during the constant-velocity window, so downstream detection hardware knows exactly when to count photons and when to ignore.

The engine supports both unidirectional scanning (collect on the forward sweep, flyback, repeat) and bidirectional scanning (collect in both directions).

Scan Geometry and Axes

Any physical axis can be assigned as the fast or slow axis, so the same engine handles XY, XZ, YZ, and full XYZ volumetric scans. Each axis has its own scaling and offset registers, so you can reposition or resize the scan field on the fly. Multi-frame acquisition (Z-stacks, time-lapse) is built in.

Line Pattern Sets

For multi-color imaging you often need different laser lines on different scan lines. The engine has a programmable pattern set where you define which laser is active on each line, how many times it repeats, and in what order. The pattern loops automatically across the frame.

FPGA and DAC

Everything runs on an FPGA for deterministic, cycle-accurate timing. The host loads all parameters (speed, acceleration, pixel dwell, line count, axis assignments, pattern sets, etc.) into registers, hits start, and the FPGA takes over. It computes positions every clock cycle then streams them to 20-bit DACs. The 20-bit resolution gives positioning granularity well below the diffraction limit, so the DAC is never the bottleneck. 

-- Simplified scan state machine (VHDL-style pseudocode)
process(clk)
begin
  if rising_edge(clk) then
    case scan_phase is
      when ACCEL =>
        velocity <= velocity + acceleration;
        position <= position + velocity;
        if velocity >= target_speed then
          scan_phase <= CONST_VEL;
        end if;

      when CONST_VEL =>
        position <= position + target_speed;
        pixel_valid <= '1';
        if pixel_count >= pixels_per_line then
          scan_phase <= DECEL;
          pixel_valid <= '0';
        end if;

      when DECEL =>
        velocity <= velocity - acceleration;
        position <= position + velocity;
        if velocity <= 0 then
          scan_phase <= TURN;
        end if;

      when TURN =>
        -- reverse for bidirectional, or flyback
        scan_phase <= ACCEL;
    end case;
  end if;
end process;

GUI

Everything is controllable from a host-side GUI: pixel/line counts, speed, acceleration, axis roles, scaling, offsets, scan direction, frame count, and pattern sets. Parameters propagate to the FPGA registers live, so you can tweak the scan field or swap laser patterns without reprogramming the FPGA.

Results

The engine produces clean rasters across all scan planes. Line pattern sets have been validated with multi-laser setups. The system is integrated into an active microscopy setup at MPI-CBG and used for routine imaging.
